# ADR-0002：图谱渲染采用 Sigma.js WebGL，活布局跑在主线程

日期：2026-09-29 · 状态：已接受

## 背景

全局图约 500 节点，需要力导向活布局（入场聚拢动画、拖拽联动）与大量曲线边渲染。
此前 Canvas 2D 方案在动画与交互流畅度上不达标。

## 决策

- 渲染层用 **Sigma.js 3（WebGL）** + `@sigma/edge-curve` 贝塞尔曲线边。
- ForceAtlas2 布局以**主线程 rAF 循环**逐帧 `assign`（每帧 2 次迭代，约 500 节点耗时 ~1ms），
  **不使用 worker supervisor**。
- 布局参数面向收敛调校：`gravity: 2.0`（向心聚拢）、初始散布半径 `2.0·√i`、
  活动期约 5 秒后静置；位置归一化只在静置后执行一次。

## 理由

实测中 FA2 的 worker supervisor 在部分打包环境下会让 WebGL 渲染**静默失效**
（画布空白且无任何报错），主线程方案渲染路径全程可靠。
归一化若在布局活动中逐帧执行，会与布局的自然尺度趋势产生帧级锯齿（视觉抖动），
因此收敛与归一化的时机被固定为"先收敛、静置后归一"。

## 后果

- 正面：动画与拖拽稳定；布局在数秒内收敛为稳定视图。
- 代价：布局计算占用主线程（当前规模下约 1ms/帧，可接受）；节点量级显著增长时
  需重新评估（届时可探索 OffscreenCanvas + 显式消息协议，而非 worker supervisor）。
